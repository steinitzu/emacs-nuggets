# md-table-align benchmark results

Recorded runs of `make bench` (tests/bench-tables.el via tests/run-bench.sh).
Each run appends one section: `tests/run-bench.sh >> tests/bench-results.md`.

How to read the numbers:

- **Call counts are the regression signal.**  `string-pixel-width`,
  `layout-table` (table layout passes), `measure passes` (full re-parse and
  re-measure of a table's cells) and `split-at` (viewport clip-boundary
  searches) are deterministic for a given fixture, frame size (pinned at
  400x60 by the runner) and code.  A count that grows without a deliberate
  behavior change is a regression.
- **Wall and GC times are machine-dependent** — comparable only loosely, and
  only across runs on the same machine.  They also understate GUI cost: on a
  TTY `string-pixel-width` is ~20 µs, in a GUI it does real font shaping at
  0.1–1 ms per call.  See docs/many-tables-open-resize-performance.md.

The fixture is generated by the harness (deterministic, 8 tables, half of
them ~900-char lines, so every wide table is clipped by the viewport).
Changing the fixture or the frame size resets the baseline — note it here
when that happens.
