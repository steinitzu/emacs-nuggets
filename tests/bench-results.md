# md-table-align benchmark results

Recorded runs of `make bench` (tests/bench-tables.el via tests/run-bench.sh).
Each run appends one section: `tests/run-bench.sh >> tests/bench-results.md`.

How to read the numbers:

- **Call counts are the regression signal.**  `string-pixel-width`,
  `layout-table` (table layout passes), `measure passes` (full re-parse and
  re-measure of a table's cells) and `split-at` (viewport clip-boundary
  searches) are deterministic for a given fixture, frame size (pinned at
  400x60 by the runner) and code.  A count that grows without a deliberate
  behavior change is a regression.
- **Wall and GC times are machine-dependent** — comparable only loosely, and
  only across runs on the same machine.  They also understate GUI cost: on a
  TTY `string-pixel-width` is ~20 µs, in a GUI it does real font shaping at
  0.1–1 ms per call.  See docs/many-tables-open-resize-performance.md.

The fixture is generated by the harness (deterministic, 8 tables, half of
them ~900-char lines, so every wide table is clipped by the viewport).
Changing the fixture or the frame size resets the baseline — note it here
when that happens.

## 2026-08-27 — b5be635

Three vertical scenarios added this run: all 8 tables toggled vertical,
then the resize and page-through passes repeated.  The horizontal rows
are the baseline for comparison; `split-at` is structurally 0 for
vertical tables (no viewport to clip).  Vertical relayout is cheaper
than horizontal across the board: no clipping, and only labels and the
pipe are re-measured per pass (56 calls for the initial 8-table toggle
is exactly 48 labels + 8 pipes).  `layout-table` is higher when paging
vertically because records render ~4x more screen lines, so the same
buffer is more pages.

## 2026-09-17 — 494d8c1

Margin spill (v9).  The fixture is benched without margins, so nothing
spills here and the point of the run is that the ordinary path did not
get more expensive.  `layout-table`, measure passes and `split-at` are
unchanged; `string-pixel-width` gains **two calls per table
measurement** — `md-table-align--fixed-pitch-p` measuring `l` against
`W` — which the metrics cache then holds with the rest of the context.

Wall and gc times ran roughly 2x the previous entry across every
scenario, vertical rows included, which is the sandbox this was measured
in rather than a change in the code; the call counts are the signal.
